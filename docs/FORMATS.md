# 文件、配置与路径契约

## 原生脑图：MM-ZSH-1

`.mm` 是 UTF-8 纯文本，首行为 `MM-ZSH-1`，随后每行以两个 Tab 分隔三个字段：深度、折叠标记、节点文字。示意中的 `\t` 表示真实 Tab：

```text
MM-ZSH-1
0\t0\t中心主题
1\t1\t折叠分支
2\t0\t隐藏但保留的子节点
1\t0\t其他分支
```

节点按先序排列；第一节点深度为 0，其他节点为正整数，不能比前一节点的深度增加超过 1。模型保留一个根节点，不设节点数量和层级的固定上限。深度接受任意位数的十进制数字，数值必须为 JavaScript 可准确表示的安全整数；保存时输出规范数字。折叠只能为 `0` 或 `1`。

文字不设长度上限，但不能为空或全为空白，不含 Unicode 控制字符，不允许 Tab 和换行。字段外不添加注释或空白行。读取接受 LF、CRLF 和末行没有换行；写出统一 LF 并保留末行换行。文件内容从不执行为脚本。旧文件继续兼容；超过旧版容量限制的新文件需要使用取消上限后的版本打开。

运行期 ID、布局模式、选择、视口、剪贴板和撤销历史不进入 `.mm`。读取分配新 ID，保存保留所有节点原文及折叠状态。仅操作折叠不标记未保存，手动保存仍会写入当前折叠状态。

## Markdown 大纲

导出格式为一个 H1 根标题和无序列表。一级子节点无缩进，每增加一层加两个 ASCII 空格，不设列表深度上限。

```markdown
# 中心主题
- 一级节点
  - 二级节点
- 另一个一级节点
```

导入接受 `#` 至 `######` 标题，`-`、`+`、`*` 无序列表，以及 LF／CRLF、空白行。列表使用相对缩进：空格数量不限，Tab 按 4 列制表位展开；每次增加缩进深入一层，减少时回到最近的较浅父层。标题以最近较小级别的标题为父节点，跳级归一化，不创建空节点。标题下的列表从该标题下一层开始。

单一顶层标题直接作为根节点；有多个顶层标题或第一项是列表时，自动添加“导入脑图”总根，并将所有原节点整体下移一层，文字与顺序不变。重复标题也各自保留。导入不设节点数、层级或文字长度上限；有序列表、正文段落、表格、代码块及多行列表内容仍明确报告原文件行号并整体失败，不返回部分结果或丢弃不支持的内容。

标签按纯文本处理。导出对所有 ASCII 标点加反斜线，标签首尾 ASCII 空格写成 `&#32;`；导入按顺序还原，避免对已经转义的实体二次解码。支持数字实体及 `amp`、`lt`、`gt`、`quot`、`apos`、`nbsp`，其他未识别实体保留字面文字。非法 Unicode 数值或解码后产生控制字符会报错。加粗、链接等内联语法不另作富文本解释。

往返保证包括文字、父子关系、兄弟顺序；导出遍历全部节点，包含隐藏后代。Markdown 不保存折叠、布局或会话信息，导入后全部展开。界面导入创建未保存的新文档；导出不更改当前原生文档的路径或未保存状态。

## 当前配置：版本 2 JSON

应用 1.0.1 起使用版本 2 配置。默认文件为用户主目录下 `Shell Mindmap/.app/config.json`，属于当前用户跨工作目录共用的应用资料。`MM_CONFIG_FILE` 可指定其他位置，开头 `~` 允许展开，路径最后解析为绝对路径。实际程序代码仍由 npm 标准安装位置管理，与此配置目录分开。

JSON 字段为：

| 字段 | 类型与含义 |
| --- | --- |
| `version` | 固定为数字 `2` |
| `saveDir` | 默认 `""`，动态使用启动工作目录；非空值为显式的全局保存目录覆盖 |
| `nodeWidth` | 8–80 的整数终端列数，默认 32 |
| `layout` | `right` 或 `bilateral`，默认 `right` |
| `keys` | 动作名到主键字符串的对象 |

字段名称与 CLI 展示名称不同：`saveDir` 对应 `save-dir`，`nodeWidth` 对应 `node-width`，`keys.help` 对应 `key.help`。有效保存目录在运行期将空值解析为启动 `SMM` 所在目录，不能反过来将该绝对目录写入配置。修改布局、宽度、快捷键等字段时保留 `saveDir: ""`；`config reset save-dir` 恢复空值。通过 `SMM config`／`SMM keys` 获取完整有效值，比手写不完整 JSON 更稳妥。目录浏览器新建文档时另存所选目录，该文档状态不写入全局配置。

未知顶层字段、未知动作、无效类型、缺失原版动作字段和非空主键冲突均拒绝。1.1.0 起所有动作都允许空字符串表示取消主键，原版动作字段仍须存在。固定命令及帮助入口不受取消主键影响。配置保存前完成校验，不会为了写入非法设置破坏当前配置。

普通主键支持单个可见字符，或 `Tab`、`Enter`、`Left`、`Right`、`Up`、`Down`、`Space`、`Delete`、`Backspace`、`PageUp`、`PageDown`，以及 `Shift+Left`、`Shift+Right`、`Shift+Up`、`Shift+Down`、`Ctrl+f`。`F1` 只允许绑定 help。`/`、`:`、`：` 是固定命令入口，`？` 是固定帮助入口，均不能新分配给任何动作。主键优先于便捷别名；除此之外的组合快捷键与连续按键绑定不属于配置格式。

1.0.3 新增 `pan-left/right/up/down` 动作，默认主键为 H/L/K/J，便捷别名为对应 Shift 方向键。读取旧版 JSON 时补齐缺少的动作；已有键位冲突时保留用户绑定并取消相应新增主键，不需要修改配置版本。

1.1.0 的搜索主键默认为 `f`，便捷别名为 `Ctrl+f`，也可用 `/search`。命令输入显示 `/` 前缀，节点搜索显示 `?` 前缀；这些显示前缀不属于输入数据或存储格式。

## 旧配置迁移

版本 1 JSON 的 `saveDir` 若与当时默认 `~/Shell Mindmap` 相同，迁为版本 2 的空字符串；其他显式保存路径保留。版本 1 无法区分该默认路径是否曾被用户手动选择，因此迁移后仍想固定使用该目录的用户需要重新执行 `SMM config set save-dir "~/Shell Mindmap"`。版本 2 中这一显式路径会被保留，不再次视作默认值。

旧文件为 `MM-CONFIG-1` 文件头，加 Tab 分隔的键值行。原版配置项包括 `save-dir`、`node-width` 和原版 `key.ACTION`；兼容读取 `key.search`。未知键、重复定义、非法值、未被下述迁移消解的主键冲突均拒绝，不执行 Shell 数据。

没有新配置且未设置 `MM_CONFIG_FILE` 时，回读 `$XDG_CONFIG_HOME/mm/config`，未设置 XDG 时回读 `~/.config/mm/config`。只读命令只加载和解释兼容格式；进入交互界面或写入设置时才持久化版本 2。旧文件迁到新位置时保留源文件；同一文件需要从版本 1 JSON、旧 Zsh 格式或含旧 `/` 绑定的版本 2 JSON 替换时，先创建带时间戳和 UUID 的 `.backup-*` 文件，再原子替换。

版本 1／2 JSON 和 `MM-CONFIG-1` 的旧搜索主键 `/` 会改为 `f`；如果其他动作已使用 `f`，搜索主键改为空字符串，不抢占已有键。其他动作中的旧 `/` 主键全部取消，原版动作同样可以为空。已有非 `/` 自定义搜索键保持不变。缺少搜索字段时按新增动作补默认值，同样让已有 `f` 绑定优先。搜索仍可通过 `Ctrl+f` 便捷别名或 `/search` 使用；用户主动给其他动作绑定 `Ctrl+f` 时，仍遵守主键优先规则。这次迁移保持配置版本 2，迁移失败保留原文件。

旧 Zsh 的空 `save-dir` 保持为空，动态使用启动工作目录；非空目录保持其显式选择，包括 `~/Shell Mindmap`。原版键位覆盖新增默认键；遇到冲突时取消该新增动作的主键，命令入口仍可使用。损坏配置可用 `SMM config reset` 恢复；目标文件需要替换且为旧格式或损坏内容时会先备份。所有这些迁移只更新配置，不移动已有脑图。

## 恢复快照

恢复文件位于固定应用公共目录 `~/Shell Mindmap/.app/recovery/<sessionId>.json`，与工作目录和配置的 `save-dir` 无关。内部记录为 `sessionId`、`nodes`、可选 `file`、可选 `baseFingerprint`、可选 `saveDirectory` 和 ISO 格式 `updatedAt`。节点保留运行期 ID；已有文件路径为绝对路径，指纹为 64 位十六进制 SHA-256。

1.2.0 新增可选 `saveDirectory`，记录从目录浏览器新建时明确选择的目录，保存快照前规范化为绝对路径。恢复后首次保存、相对 `/write`／另存为／导出优先使用该目录；已有 `file` 的普通保存仍使用原文件绝对路径。旧快照不含此字段时继续读取，使用既有保存目录规则。字段存在时必须为不含控制字符的规范绝对路径，不能是空字符串、相对路径或其他类型；不要求该目录仍然存在，后续保存时再报告路径错误，不能因此丢弃可恢复内容。

这是应用内部恢复数据，不作为用户交换格式。恢复列表校验文件名与会话 ID、时间、路径、指纹及完整模型；无效记录跳过。恢复后文档处于未保存状态，原文件指纹继续参与保存冲突检测。

## 路径与写入

| 入口 | 相对路径解释 |
| --- | --- |
| `SMM FILE`，一般界面打开／导入 | 启动时的工作目录 |
| CLI `SMM import/export INPUT -o OUTPUT` | 输入和输出都以启动时的工作目录为准 |
| 目录浏览器 `o` 直接输入路径 | 当前浏览目录；支持文件或目录 |
| 界面首次保存、另存为、`/write PATH`、导出 | 文档有 `saveDirectory` 时优先使用它；否则使用显式 `save-dir` 或启动工作目录 |
| 无参数 `SMM` | 始终浏览启动目录，不受 `save-dir` 影响；目录树按展开操作逐层读取 |
| 编辑器 `O` | 从当前文件父目录或上次浏览位置打开目录浏览器 |
| `SMM list` | 列出显式 `save-dir` 或启动目录中的 `.mm` 文件，不递归子目录 |
| 已打开文件的普通保存 | 已记录的绝对文件路径 |

`SMM` 为主命令，`mm` 保留兼容。命令改名不改变 `.mm` 文件格式、`MM_*` 环境变量或旧配置搜索位置。浏览目录不调用 `process.chdir`，也不修改全局 `save-dir`；展开状态、筛选、目录树选择和活动区域不写入 `.mm`。

`~`、`~/` 以及平台支持的主目录分隔形式会展开；不展开环境变量、通配符或命令替换。命令框解析保留 Windows 路径分隔符，允许对空白、引号和反斜线转义。外层 Shell 如何解释用户输入由其自身规则决定。

交互启动会为公共资料创建所需的 `~/Shell Mindmap` 目录。脑图工作目录和其他目标父目录要求已存在，不因保存自动建立工作区。已有主目录脑图继续保留原地；从其他目录打开后，普通保存仍写回原路径。脑图／配置目标必须是普通文件，不接受符号链接或特殊文件。写入使用同目录临时文件、文件同步和原子替换，错误不会先删除原文件。界面另存到已有文件需确认；CLI 转换不覆盖已有文件。
