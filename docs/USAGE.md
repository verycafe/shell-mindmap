# Shell Mindmap 使用指南

> 1.2.2 采用左侧目录树、右侧脑图的双栏布局，窄窗口使用页签。返回 [项目首页](../README.md)。

在终端里整理想法：输入节点，用键盘添加和移动分支，自动排版、搜索、保存与恢复。界面由 Ink 和 React 实现，脑图仍保存为兼容原版的 `.mm` 纯文本文件。运行时不调用 AI、浏览器或云服务。

当前版本 **1.2.2**：使用 `SMM` 启动，先浏览当前目录的子文件夹和脑图文件，再打开或新建脑图。`/` 打开可筛选的命令菜单。旧 `mm` 命令保留为兼容入口。

## 安装与运行

需要 Node.js 22 或更高版本、npm 11.10.0 或更高版本，以及支持 ANSI、UTF-8 的交互终端。项目固定使用 npm 11.10.1；Python 仅供 macOS/Linux 的终端集成测试使用。

在项目根目录执行：

```sh
npm ci
npm run build
npm link
SMM
```

`npm link` 将 `SMM` 接到当前项目，之后修改源码需要重新执行 `npm run build`。不需要加载 Zsh 函数，也不修改 Shell 配置。暂不链接全局命令时，可以执行 `node bin/SMM.js`。更新本地代码后，先退出正在运行的 `SMM`，重新构建再打开原文件。

如果找不到 `SMM`，检查 npm 全局命令目录是否在 PATH 中；Windows PowerShell 若阻止执行 npm 的脚本包装，可使用 `npm.cmd` 和 `SMM.cmd`。旧 `mm` 命令仍可使用；若当前 Zsh 中残留旧版 `mm` 函数，它可能遮住兼容入口，可执行 `unfunction mm` 并移除旧版加载行。新入口 `SMM` 不受旧 `mm` 函数影响。

程序代码由 npm 的标准安装位置管理；使用 `npm link` 时，命令链接到开发项目。当前用户的配置和恢复资料由各工作目录共用，放在主目录中的 **Shell Mindmap**：

| 系统 | 应用公共资料目录示例 | 运行方式 |
| --- | --- | --- |
| macOS | `/Users/用户名/Shell Mindmap` | 终端中执行 `SMM` |
| Linux | `/home/用户名/Shell Mindmap` | 终端中执行 `SMM` |
| Windows | `C:\Users\用户名\Shell Mindmap` | PowerShell、命令提示符等终端中执行 `SMM` |

这个公共目录取自 Node.js 的用户主目录，配置位于 `.app/config.json`，恢复快照位于 `.app/recovery`。首次进入交互界面会创建所需公共目录；它的位置不随工作目录或 `save-dir` 改变。

**无参数执行 `SMM`，始终先展示启动目录。** 进入哪个项目，就从哪个项目查找脑图，不需要重复安装程序。例如先进入一个已存在的项目目录：

```sh
cd ~/Projects/项目
SMM
```

首页分为两个独立滚动区域：**左侧是目录树，右侧是当前目录的脑图文件**。目录树用缩进、连接线和展开标记表示启动位置、子文件夹及更深层级，即使有 100 个子文件夹，也不会把右侧脑图挤出屏幕。窗口不足 80 列时改为两个可切换的页签，顶部仍显示当前路径。脑图按最近修改时间排列，同级文件夹按名称排列；展开目录时才读取下一层，不预先递归扫描整棵目录树，也不显示无关类型的文件。

**当前目录和键盘选中项分开表示。** 上下键只移动目录树中的选中项，Enter 才将该文件夹设为当前目录并更新右侧脑图；展开或收起其他分支不会让正在查看的文件列表跳走。顶部路径与目录树的当前目录标记一起说明文件属于哪里。所有页面的路径、布局与节点信息、操作提示、计数、输入占位和命令空状态提示统一使用终端默认文字颜色，避免在深色或浅色主题下过淡。占位文字用斜体区分，选中项和错误提示保留强调色。

目录树顶部的 **`.. 上级目录`** 会标明目标父目录，选中后按 Enter 或 → 即可跳出这棵树，继续向上查找；选中树根按 ← 也可上跳。Backspace 始终返回当前浏览目录的父目录，到文件系统根目录时停止。

在列表中选中文件并按 Enter，就进入原来的脑图编辑界面。按 `n` 新建，在当前浏览的文件夹输入中心主题，第一次保存默认使用这个文件夹；这次明确选择的位置优先于全局 `save-dir`。浏览其他目录不会移动已经打开的文件，也不会修改终端的工作目录或全局设置。

`SMM list` 仍是非交互的脑图文件列表，默认列出启动目录，显式 `save-dir` 可覆盖；`SMM config reset save-dir` 恢复动态目录。交互首页始终从启动目录开始，不受该设置影响。

以前已经保存在 `~/Shell Mindmap` 的脑图继续留在原地，不会自动搬到某个项目。可用 `SMM "~/Shell Mindmap/文件.mm"` 打开，普通保存仍写回该文件原路径。

项目提供三系统、Node.js 22/24 的 CI 配置；**本次本地工作环境为 macOS，尚不能据此宣称 Linux、Windows 的实机终端体验已通过验证**。不同终端与中文输入法的候选窗口仍需人工体验确认。

## 目录首页：打开或新建

运行 `SMM` 后，顶部显示当前浏览路径，左侧显示目录树，右侧显示该目录的脑图。存在脑图时默认激活脑图区，否则激活目录树；按 Tab 切换区域。底部始终显示 `n 新建` 入口。要查找二级目录中的文件，先在树中展开一级目录，再选中二级目录并按 Enter；按 Tab 即可选择右侧脑图。

| 按键 | 操作 |
| --- | --- |
| Tab | 切换目录树／脑图区；窄窗口切换页签 |
| ↑ / ↓ | 在当前区域选择上一个／下一个条目 |
| PageUp / PageDown | 当前区域翻页；Mac 可用 Fn＋↑／↓ |
| Home / End | 跳到当前区域开头／末尾；目录树开头是上级入口（若存在） |
| Enter | 打开上级入口或激活所选目录并更新脑图列表；脑图区中打开所选脑图 |
| → | 上级入口直接进入；普通目录展开或选中第一个子目录；脑图区中打开文件 |
| 空格 | 展开／收起所选目录，不切换当前目录 |
| ← | 收起所选目录；已收起时选中其父目录；选中树根或上级入口时向上跳出 |
| Backspace | 将当前目录切换到上一级 |
| `n` | 在当前浏览目录新建脑图并进入编辑 |
| `f` | 按名称筛选已加载的目录树和当前目录脑图，选中实际匹配项；Enter 保留，Esc 清除，不递归搜索未展开目录 |
| `.` | 显示／隐藏以点开头的条目 |
| Ctrl-R | 刷新目录和文件列表 |
| `o` | 输入文件或目录路径，直接打开或跳转 |
| `r` | 查看崩溃恢复快照 |
| `/`，F1 | 命令菜单；帮助 |
| Esc | 先清除筛选；无筛选时，从编辑进入的浏览器返回原脑图 |
| `q` | 退出 |

筛选时保留匹配文件夹的祖先，以便看清层级；要收起分支，先按 Esc 清除筛选。

已有完整路径时，执行 `SMM 文件.mm` 可以直接进入编辑，跳过目录首页。相对路径以启动命令时的工作目录为准。文件不存在时创建新脑图，实际写盘需保存。文件名与子命令重名或以 `-` 开头时，使用 `SMM -- 文件名`。

## 开始整理一张脑图

1. 在目录首页按 `n`，输入中心主题并按 Enter。按 Tab 添加子节点，按 Enter 添加同级节点，按 `e` 修改文字。
2. 用方向键选择节点，空格折叠分支。长节点自动换行；选中节点会进入可见区域。PageUp/PageDown 翻页，Shift＋方向键平移视口，`g` 或 Home 回到根节点并居中。终端拦截组合键时，可用大写 `H/J/K/L` 分别向左／下／上／右查看。
3. 按 `f`、Ctrl-F 或执行 `/search` 搜索所有节点，包括折叠中的内容；上下键选择结果，Enter 展开祖先并定位。搜索匹配不区分大小写。
4. 按 `c` 复制当前分支，选择目标后按 `p` 粘贴为子分支。按 `m` 选择新的父节点；`[`、`]` 调整同级分支顺序。一次移动或粘贴可以用一次 `u` 撤销。
5. 按 `s` 保存。新脑图建议使用中心主题作为文件名；从目录首页新建时默认保存在刚才浏览的文件夹。按 `S` 另存为，按 `O` 返回文件浏览器查找其他脑图。打开新文件或新建前会处理未保存修改。按 `q` 退出，有未保存修改时可保存、放弃或返回。

编辑中的 `O` 从当前文件的父目录开始，未命名脑图则从上次浏览的位置开始。只查看目录不会丢弃当前编辑；按 Esc 即可返回。下面是**脑图编辑界面**的快捷键，与目录首页按模式分别处理。

## 默认快捷键

| 按键 | 操作 |
| --- | --- |
| Tab / `a` | 添加子节点 |
| Enter / `o` | 添加同级节点；根节点不允许 |
| `e` | 编辑文字 |
| ← / `h`，→ / `l` | 选择父节点；展开并选择首个子节点 |
| ↑ / `k`，↓ / `j` | 选择上一个／下一个可见节点 |
| 空格 | 折叠／展开 |
| `d` / Delete | 删除当前分支；根节点不允许 |
| `u` / `r` | 撤销／重做，最多保留 30 次修改 |
| `s` / Ctrl-S，`S` | 保存；另存为 |
| `f` / Ctrl-F | 搜索并定位 |
| `c` / `p` | 复制分支／粘贴为子分支 |
| `m`，`[` / `]` | 移动到新父节点；同级分支上移／下移 |
| `g` / Home | 回到根节点并居中 |
| PageUp / PageDown | 垂直翻页；Mac 可用 Fn＋↑／↓ |
| Shift＋方向键，`H/J/K/L` | 平移视口；字母分别对应左／下／上／右 |
| `,`，`O`，`N` | 设置；文件浏览器；新建脑图 |
| `I` / `E` | 导入／导出 Markdown |
| `?` / `？` / F1 | 帮助 |
| `/`，兼容 `:` / `：` | 打开命令菜单，输入英文命令或中文描述筛选 |
| `q` | 退出 |

双侧布局中左右键仍表示父子关系，不随节点在画布上的左右位置改变。帮助中 Enter 保持帮助，上下键滚动、翻页键翻页，Esc 返回。文字编辑支持左右、Home/End、退格、Delete、Ctrl-U 清空、Enter 确认、Esc/Ctrl-C 取消。F1 可临时打开帮助并返回原输入；从命令菜单返回时保留原来选中的候选。

中文、组合字符和 emoji 按字素簇编辑。终端支持的带边界粘贴只作为文字输入，换行和 Tab 转为空格；浏览模式不会执行粘贴中的快捷键。最小可用窗口为 48 列 × 12 行。

输入区域使用圆角边框和用途标题，空输入显示示例提示；节点编辑显示 `已输入/300`，与文件格式的 Unicode 码点上限一致。命令输入以 `/` 标记，节点搜索输入以 `?` 标记；下方分别提示候选选择、搜索结果选择或文字编辑操作。长文字和路径横向滚动，光标始终保留在框内；占位提示不会写入文件。

当前没有应用内的脑图缩放快捷键。Shift＋方向键用于平移，`node-width` 改变节点换行宽度；终端字号由终端程序自身控制。

从 1.0.3 起，小脑图也可以自由平移，不再被内容边界固定住。平移仅在浏览模式生效：若正在输入文字，先按 Enter 完成或 Esc 取消。向右查看时，节点在屏幕上向左移动；向下查看时，节点向上移动。节点移出窗口后按 `g` 或 Home 回根。也可执行 `/pan-left`、`/pan-right`、`/pan-up`、`/pan-down`，它们与快捷键共用同一动作，不修改脑图内容。已有自定义 H/J/K/L 绑定优先保留。

## 配置与命令

默认布局为 `right`（向右）。双侧布局 `bilateral` 将一级分支依次安排到右、左两侧，后代跟随所属分支。

```sh
SMM help
SMM list
SMM config
SMM config path
SMM config set layout bilateral
SMM config set layout right
SMM config set node-width 40
SMM config set save-dir "~/Documents"
SMM config reset save-dir
SMM keys
SMM keys bind help F1
SMM keys reset help
SMM config reset node-width
SMM config reset
```

`save-dir` 是可选的全局保存目录，自定义目录必须已经存在且可写；空值或重置表示使用每次启动时的工作目录。它继续作用于编辑器中 `/new` 等非浏览器入口的新建和相对保存／导出路径；从目录浏览器新建时，当前目录作为这张文档的保存位置，其首次保存、相对 `/write`／另存为／导出均优先使用该目录，恢复后也保留。它不会改变启动首页的位置。修改布局、宽度或快捷键不会把当时的工作目录保存成全局目录。节点宽度默认 32 列，可设 8–80 列，窄窗口会进一步收窄。环境变量 `MM_NODE_WIDTH` 在启动时覆盖持久宽度；界面内修改宽度对本次会话立即生效，下次启动仍会读取环境变量。

配置默认为 `~/Shell Mindmap/.app/config.json`；`MM_CONFIG_FILE` 可以指定其他完整文件路径。当前 JSON 格式为版本 2，`saveDir: ""` 代表动态工作目录。版本 1 中与当时默认 `~/Shell Mindmap` 相同的保存目录会迁成空值，其他显式路径保留；如果仍希望所有脑图统一保存到主目录下的 Shell Mindmap，可重新显式设置该路径。

只读配置命令不会创建配置文件。交互启动在需要时迁移旧配置；新配置不存在时也可读取旧 `$XDG_CONFIG_HOME/mm/config` 或 `~/.config/mm/config`。旧 Zsh 的空保存目录恢复动态工作目录，非空路径保留。迁移保留源文件，原位置需要替换时先备份。旧版自定义快捷键优先；与其冲突的新增动作不会抢占按键，仍可通过命令执行。配置迁移不会移动任何脑图。

快捷键设置名为 `key.ACTION`，动作名见 `SMM keys`。支持单个可见字符或 Tab、Enter、Left、Right、Up、Down、Space、Delete、PageUp、PageDown，以及 Shift+Left、Shift+Right、Shift+Up、Shift+Down、Ctrl+f。F1 仅能分配给 help；F1 和中文问号保留帮助入口，`/`、英文／中文冒号保留命令入口。不能将 `/` 分配给任何动作。自定义主键优先于便捷别名；所有动作均可绑定空值以取消主键，例如 `SMM keys bind search ""`。设置只改变浏览模式按键。

1.1.0 会将旧配置中搜索的 `/` 主键改为 `f`；如果其他动作已占用 `f`，就取消搜索主键，仍可使用 Ctrl-F 或 `/search`。其他动作原来绑定的 `/` 也会取消，已有非 `/` 自定义搜索键保留。这同样适用于版本 1／2 JSON 和旧 `MM-CONFIG-1`；只读查看不改原文件，交互启动或实际写设置时备份并原子持久化迁移，配置版本仍为 2。

在浏览模式按 `/` 打开命令菜单，`:`、`：` 仍可作为兼容入口。也可以在空的节点编辑、添加子节点或添加同级节点输入框中实际键入 `/` 打开菜单。候选包含英文命令和中文描述，支持子串、按顺序跳字的子序列模糊筛选；例如输入“保存”或 `wrt` 查找 `write`。上下键选择，PageUp/PageDown 翻页，Tab 补齐候选。Enter 执行当前候选；需要必填参数的候选只补齐输入，等待填写参数后再执行。

Esc 返回调用菜单前的空编辑；从浏览模式进入时返回浏览。查看帮助或修改设置等操作可继续原来的空编辑；明确选择编辑节点、添加节点、新建或打开文件等动作时，会进入相应的新上下文。F1 临时查看帮助后，返回时保留菜单输入与候选位置。

空节点编辑中需要字面 `/` 时，连续键入 `//` 得到一个 `/`。已有文字的节点输入、文件路径输入中的 `/` 都是普通文字；粘贴不会触发命令菜单。以下示例开头的 `/` 是菜单入口，不需要在打开后的输入框里重复输入：

```text
/help
/settings
/set layout bilateral
/set node-width 40
/bind help F1
/reset keys
/write "我的脑图.mm"
/open
/open "其他脑图.mm"
/search "需求"
/copy
/paste
/move
/move-up
/move-down
/root
/new
/import "大纲.md"
/export "大纲.md"
/recover
/quit
```

`/help` 显示全部命令，`/config`、`/keys` 打开设置；`/write` 与 `/quit` 可简写为 `/w`、`/q`。旧的 `:help`、`:write` 等写法继续可用。含空格路径请加引号。命令框支持字面引号、必要的反斜线转义和开头的 `~/`；不执行 Shell，不展开变量或通配符。通常打开和导入的相对路径以启动时的工作目录为准；目录浏览器中的直接路径入口按当前浏览位置解释。保存、另存为和导出的相对路径默认使用启动目录，仅在显式设置 `save-dir` 时改用覆盖目录；从目录浏览器新建的脑图使用所选目录作为保存位置，恢复后仍保留。已打开文件按 `s` 始终写回原路径，不受后续设置变化影响。

## Markdown 与原生文件

`.mm` 继续使用 `MM-ZSH-1` 格式，可直接打开历史脑图。每张图最多 500 个节点、24 层，每个节点最多 300 个 Unicode 码点；字素簇编辑与此存储上限是不同的计数方式。折叠是视图操作，不单独标记未保存；手动保存仍会记录折叠状态。

Markdown 使用明确的大纲格式：

```markdown
# 项目主题
- 产品
  - 用户需求
  - 交互设计
- 研发
```

只允许一个 `# 根标题` 和每层缩进 2 空格的单行无序列表；可用 `-`、`+`、`*`，允许空行和 Windows 换行。正文段落、多级标题、有序列表、表格、代码块和多行列表内容会报错并指出行号。列表内的加粗、链接等标记按普通节点文字保留，不解释富文本。

导出包括折叠中的后代，转义 Markdown 标点并保存首尾空格；重新导入可保留文字、树结构和兄弟顺序，全部节点展开。布局、选择和撤销历史不进入 Markdown。界面内导入生成待保存的新脑图，导出不改变当前文件或未保存状态。

无需进入界面也能转换；输入输出相对路径均以工作目录为准，命令行转换拒绝覆盖已有文件：

```sh
SMM import outline.md -o outline.mm
SMM export outline.mm -o outline.md
```

## 保存、恢复与常见问题

内容修改后约 1 秒写入独立恢复快照，位置为 `~/Shell Mindmap/.app/recovery`。快照不会自动覆盖原脑图。无参数启动发现快照时，目录首页显示恢复提示，按 `r` 或使用 `/recover` 查看，不会挡住文件列表；带文件参数启动保留原来的恢复列表提示。上下键选择、Enter 恢复，检查内容后按 `s` 保存。删除快照需按 `d` 并确认。正常保存或明确放弃修改后清理对应快照。

强制终止、断电或系统崩溃前尚未写入的最后约 1 秒内容可能无法恢复。可处理的退出信号会尝试补写快照；损坏的快照会被跳过，不影响其他可恢复会话。

| 提示／情况 | 处理方式 |
| --- | --- |
| 文件已被其他程序修改 | 当前编辑保留。按 `S` 选择一个不同的新文件名，或取消后重新打开磁盘文件；不会直接覆盖外部修改。 |
| 保存目录不存在 | 先创建自定义目录，或用 `SMM config reset save-dir` 恢复使用启动时的工作目录。 |
| 无法读取配置 | 先用 `SMM config path` 确认位置，再用 `SMM config reset` 恢复默认；将被替换的旧格式或损坏配置会备份。 |
| 快捷键冲突 | 先改绑占用该键的动作，或用 `SMM keys reset` 一次恢复全部主键。 |
| 窗口太小 | 放大到至少 48×12，布局会随窗口恢复。 |
| 输入不是交互终端 | 在普通终端执行 `SMM`；管道环境可使用 `help`、配置、列表和文件转换命令。 |

保存采用同目录临时文件、写盘同步和原子替换；打开时记录内容指纹，保存前核对外部变化。拒绝将脑图或配置读写到符号链接、目录、特殊文件。脑图父目录必须存在，不会因保存自动创建工作目录。

## 开发、验证与打包

```sh
npm run check
npm test
npm run test:pty
npm pack --dry-run
npm pack
```

`npm test` 构建并执行测试；PTY 测试需要 macOS/Linux、Python 3，且 Python 启动的进程能在 PATH 中找到 Node.js。CI 覆盖三系统的 Node.js 22/24，PTY 仅在 macOS/Linux 执行。本机已验证 macOS；CI 配置本身不代表其他系统的真实终端体验已通过验证。

新增或重新解析依赖时，`.npmrc` 的 `min-release-age=7` 要求版本已发布至少 7 天；需要 npm 11.10.0+ 才支持。npm 11.10.1 会将此配置归一化为截止时间，可在仓库根目录用 `npm config get before` 检查约 7 天前的截止时间；直接读取 `min-release-age` 返回空值并不表示保护失效。沿用锁文件执行 `npm ci`，不为普通代码修改升级依赖或重建锁文件。

`npm pack` 仅生成本地安装包，不会发布到 npm。包内容由白名单限定为启动器、构建产物、README、公开示例及 npm 必要元数据，不包含历史聊天、参考图、个人脑图、恢复快照或旧版完整源码。可将生成的 `shell-mindmap-1.2.2.tgz` 交给其他用户，在已安装 Node.js 的机器上执行 `npm install --global shell-mindmap-1.2.2.tgz` 后使用 `SMM`。旧 `mm` 入口继续兼容。

架构与格式说明分别见 [ARCHITECTURE](ARCHITECTURE.md)、[FORMATS](FORMATS.md)。继续开发以当前仓库为准。
