# 架构与维护边界

> 1.2.2 使用左侧目录树、右侧脑图的双栏界面。安装与验证命令见 [使用指南](USAGE.md)。

Shell Mindmap 使用 TypeScript、React 和 Ink 构建本地终端应用。主命令 `SMM` 和兼容入口 `mm` 调用同一个编译后的 CLI；CLI 将非交互命令直接分派到配置、存储与转换模块，交互界面则进入 Ink 的备用屏幕。无文件参数时先显示启动目录的文件浏览器，带文件参数时直接进入编辑。应用不需要 Zsh，也不调用云服务。

## 模型与状态事务

运行期节点为 `{id, text, depth, folded}`，以树的先序顺序存放；ID 用于选择和编辑，不写入原生 `.mm` 文件。模型模块负责单根、500 节点、24 层、300 Unicode 码点及控制字符校验。模型操作不修改输入，返回新节点数组与选中 ID；生成新节点时分配新 ID。

新增、改名、删除子树、移动、排序和粘贴都在完整校验后一次提交。新增同级节点插在原节点整个子树之后；新增子节点追加为最后一个孩子。移动禁止根节点和自身后代目标。复制产生深度归零的独立子树，粘贴重新分配 ID。搜索包含折叠后代，定位通过展开祖先使结果可见。

历史模块以 `{nodes, selected}` 保存事务前快照。内容事务最多保留 30 步撤销，提交新修改清空重做；相同内容操作不制造撤销记录。折叠、选择和搜索展开属于视图状态，不单独变脏。跨越保存点的撤销／重做保守标记未保存。

Ink 应用拥有当前文档、文件路径及指纹、配置、面板、输入框、视口和会话剪贴板。编辑、保存确认、节点搜索、命令菜单、帮助、设置、文件浏览器、移动目标和恢复列表按面板分派输入；帮助能够返回原输入框及命令候选位置。一个动作表承载动作名、说明与便捷别名，供主键解析、帮助和 CLI 动作列表使用；主键默认值和合法性由配置模块管理。命令目录复用可执行动作并补充带参数命令，菜单、说明和补全保持同源。扩展动作时同步动作表、默认键配置和处理分支，不增加独立的快捷键监听体系。

## 1.2.1 目录浏览与编辑入口

目录浏览器维护独立的当前路径、目录树的展开及已加载状态、筛选文字、隐藏条目开关、活动区域和各区选中位置。启动位置始终为进程启动时的工作目录，不受 `save-dir` 影响；浏览不调用 `process.chdir`，也不修改全局设置。目录树以启动位置为初始根节点，用缩进、连接线和展开标记显示子目录及更深层级。首次读取根目录，后续展开时才读取下一层，不预先递归扫描整棵目录树。树顶提供独立的 `parent` 类型“.. 上级目录”行，目标为当前树根的父路径；合成行不触发父层扫描，用户确认进入才读取。系统根目录不提供此行；它不计作筛选名称匹配，也不参与展开／折叠。Home 可选到父入口，首次进入仍选择实际树根或脑图。

视口固定分为左侧目录树和右侧脑图区，各自滚动；大量文件夹不得占满脑图区域。窗口不足 80 列时使用可切换的目录树／脑图页签，顶部当前路径始终可见。`.mm` 文件按修改时间从新到旧排列，同级子目录按名称排列。存在脑图时默认激活脑图区，否则激活目录树；Tab 切区，上下、翻页和 Home/End 在活动区域内选择。当前目录是决定右侧文件内容的独立状态，不能随树中选中项移动而改变；目录树单独标记当前目录。`f` 筛选已经加载的目录树条目和当前目录的脑图名称，不扫描未展开目录；Enter 保留筛选，Esc 先清除筛选。隐藏条目默认不显示，可用 `.` 切换，Ctrl-R 刷新条目。

目录树中 Enter 激活选中目录并更新右侧列表，→ 展开目录或选中第一个子目录，空格切换展开状态，← 收起目录或选中父目录；这些树形导航与实际打开文件分开。选中上级入口按 Enter／→，或选中树根按 ←，可跳出当前树根到上一层。Backspace 切换当前目录到其父目录；到文件系统根时保持位置并提示。脑图区 Enter／→ 打开所选文件；`o` 的直接路径入口允许文件和目录。底部固定显示 `n 新建`，不把新建混入文件列表。`n` 进入新脑图编辑，将当前浏览目录记录为这张新文档的 `saveDirectory`，首次保存以及相对 `/write`／另存为／导出优先使用该值，其次才使用全局 `save-dir` 和启动工作目录。该值写入恢复快照；普通保存已有文件时仍优先使用文件绝对路径。从编辑界面按 `O` 时，已有文件从其父目录浏览，未命名文档从上次浏览位置开始。浏览和筛选不替换当前文档；实际新建、打开或恢复才经过未保存修改确认，无筛选时 Esc 可返回原文档。

所有面板共用可读性约定：路径、布局／节点数量、操作说明、计数、输入提示和命令空状态继承终端默认前景色，不用 gray 或 dim 弱化。该规则覆盖编辑器、目录、帮助、设置、分支移动、恢复、确认及全部输入模式；输入占位使用斜体区分，不降低亮度。选中项、功能标题及错误提示保留语义强调色；分隔线和脑图连接线继续使用原有样式。

各面板独立分派按键，目录列表中的 `f` 筛选文件名、`r` 打开恢复列表，编辑界面的同名键仍搜索节点、重做。`/` 和 F1 保留命令及帮助入口。命令或临时输入返回时必须恢复调用面板，不能意外落入未创建文档的脑图画布。

## 1.1.0 命令菜单与输入上下文

`/` 是固定命令入口，兼容 `:` 和 `：`。浏览模式可直接打开；节点的 edit／child／sibling 输入为空时，实际键入 `/` 也可打开并记录原编辑上下文。非空节点输入和路径输入不将 `/` 解释为命令，粘贴统一走文字插入。空编辑中连续输入 `//` 返回节点输入并插入字面 `/`。

候选按英文命令、别名和中文说明做子串／子序列模糊匹配，使用稳定顺序呈现。↑↓、PageUp/PageDown 调整选中候选，Tab 补齐，Enter 执行；标为必填参数的候选只补入命令前缀，等待参数。已经开始填写的任意参数不得被模糊候选擅自替换。命令缓冲不包含显示用 `/` 前缀，节点搜索使用 `?` 显示前缀。

从空编辑打开菜单时，Esc 恢复原输入；从浏览打开时回到浏览。设置、帮助等操作可继续原空编辑，F1 帮助往返保留菜单输入和候选索引。明确编辑节点、添加节点或切换文档等动作会替换上下文，不能为所有命令无条件恢复旧输入。文档替换仍须经过未保存修改确认；菜单筛选本身不修改文档或撤销栈。

## 文本、布局与视口

文本编辑通过 `Intl.Segmenter` 按字素簇移动和删除，列宽由 `string-width` 测量。格式存储上限按 Unicode 码点计算，不能用 JavaScript 字符串长度或字素簇数量代替。粘贴去除终端控制序列，换行和 Tab 转成空格；带边界粘贴不进入浏览动作分派。

`input-field.tsx` 用 Ink `Box` 和 `Text` 呈现用途标题、圆角边框、占位示例、节点字数与操作提示。输入事件仍由应用统一处理，不引入第二套输入缓冲或键盘监听。输入组件占 5 行，错误消息在第 5 行替换操作提示；终端最后一行保持空白，避免 Ink 7 在末行有文字时将实际光标多上移一行。输入模式为画布预留 `rows - 9` 行，其余模式为 `rows - 7` 行。按显示列宽横向裁剪输入，并在行尾为实际光标预留一格；应用在渲染期间调用 `useCursor`，将硬件光标放在同一个可见位置。样式提示与文字数据分离，占位内容不进入模型或文件。

布局函数与终端界面分离。它先建立父子关系，计算换行后的节点尺寸，再从底向上为子树预留高度，从上向下放置节点和连接线。兄弟子树留空行，连接线锚定文本块中部。默认向右；双侧模式将一级分支按顺序交替分到右、左，其后代保持同侧。折叠不改变一级分支的分侧依据。

布局保存完整画布坐标；视口仅渲染可见单元格，相邻同色单元合并为文本段。宽字符被视口边缘切到一半时使用空格占位。布局计算在节点、宽度、模式或窗口宽度变化时更新；选择跟随和手动平移不需要重算整棵树。图中左右箭头始终表示父子关系，Shift＋方向键和 H/J/K/L 通过共享的 pan 动作平移视口。

手动平移不再用内容尺寸夹紧视口，允许负坐标和空白区域，小图也能移动；连续输入累计当前手动坐标，避免同一批按键覆盖前一次位移。水平一步 8 列，垂直一步 3 行，翻页采用地图模式的固定高度。`root` 动作将根节点选中并居中，退出手动平移；普通选择操作恢复跟随。平移与回根不修改内容或撤销栈。组合键仅在浏览模式规范成 Shift+方向键后交给动作解析，输入框中的方向键和 H/J/K/L 继续用于编辑。

## 文件与配置

目录分为程序代码、应用公共资料和工作内容三类。程序代码由 npm 标准安装目录管理；本开发机通过全局链接运行当前仓库内的构建结果，不把代码安装到用户主目录。`os.homedir()/Shell Mindmap` 是当前用户跨工作区共用的应用资料目录，固定保存 `.app/config.json` 与 `.app/recovery/*.json`。

工作内容默认位于启动进程时的工作目录。编辑器内 `/new` 等非浏览器入口的新脑图和 `SMM list` 使用该目录，显式 `save-dir` 可覆盖；从目录浏览器新建的文档记录明确选择的 `saveDirectory`，首次保存、相对 `write`／另存为／导出以该值为先，没有该值时才使用全局 `save-dir` 或启动目录。文件浏览器的启动位置始终是启动目录，已有文件的普通保存使用其既有绝对路径。通常打开与导入的相对路径以启动工作目录为准，目录浏览器直接输入的相对路径按当前浏览目录解释。`MM_CONFIG_FILE` 仅覆盖配置文件位置，不改变工作内容或恢复目录。

配置版本 2 将 `saveDir: ''` 作为“动态使用启动工作目录”的持久值。有效保存目录仅在运行期解析；修改任何其他设置时都必须原样保留空值，不能把当前工作目录写回配置。重置 `save-dir` 同样恢复空值。已有 `~/Shell Mindmap` 中的脑图保留原地，路径策略迁移不搬动用户内容。

原生文件读取使用严格 UTF-8 解码与模型校验，记录 SHA-256 内容指纹。存储模块检查普通文件、拒绝符号链接，并在读取前后核对文件身份和元数据。保存先核对上次读取的内容指纹，再写入同目录独占临时文件、同步数据并检查目标；已有文件通过重命名替换，新文件通过独占硬链接创建，以避免覆盖并发新建的目标。失败时清理临时文件，原文件保留。

这里的指纹用于发现外部修改，不构成跨进程锁或数据库事务。检查与替换之间仍存在操作系统级的极短竞争窗口；不应把实现描述为对所有并发写入的绝对保护。采用硬链接创建新文件也意味着目标文件系统须支持相应操作；不支持时明确报错，不降级为先删后写。

配置读取后统一校验。版本 1 中保存目录等于当时默认 `os.homedir()/Shell Mindmap` 的配置迁为版本 2 空值，其他显式路径保留；旧 `MM-CONFIG-1` 中空路径迁为空值，非空路径保留。只读命令在内存中解释兼容格式而不改文件；交互启动或配置写入才持久化迁移。写到新位置时保留旧源文件，原位置的旧格式转换或损坏配置重置先生成备份。旧主键优先于新增默认键，冲突的新增动作取消默认主键并保留命令入口。

1.1.0 继续使用版本 2 配置，默认搜索主键改为 `f`，便捷别名为 `Ctrl+f`。读取旧 JSON v1/v2 或 `MM-CONFIG-1` 时，先取消所有已保留为命令入口的 `/` 主键；若它原来属于搜索且 `f` 尚未被其他动作使用，则改为 `f`，否则搜索主键为空。非 `/` 的自定义搜索键保留。所有动作均允许空主键，但原版动作字段仍不能缺失；新绑定 `/` 被拒绝。迁移检测必须识别版本 2 中的旧 `/` 绑定，持久化前备份，不能仅按配置版本决定是否需要迁移。

## 崩溃恢复

每次会话有独立 ID。不同工作目录共用应用公共目录下的恢复存储。未保存内容在修改停顿约 1 秒后写入原子快照；恢复记录包含节点、原文件位置、原文件指纹和更新时间；从目录浏览器新建的未命名文档还通过可选 `saveDirectory` 保留所选保存目录，写入时解析为绝对路径，避免在其他工作目录恢复时改变保存建议位置。读取兼容不含该字段的旧快照；校验字段类型和绝对路径，但不要求目录仍然存在，避免目录移动后隐藏可恢复的文字。可处理的退出信号尝试补写。快照不代替用户保存，不修改原 `.mm`，恢复一个已有文件时继续使用其原路径。

无参数启动在目录首页提示其他会话的有效快照数量，由 `r` 或 `recover` 命令打开列表；带文件参数启动保留恢复列表提示。损坏文件被跳过。恢复建立未保存文档，后续写原文件仍核对原指纹。正常保存、明确放弃或删除恢复记录后清理相应快照。强制终止前尚未完成的防抖写入无法保证保留。

## 验证与发布边界

模型与格式测试验证不变式和往返；布局、文本测试验证宽字符、折叠、双侧与视口；配置、存储和恢复测试使用隔离的临时目录。交互状态和真实 PTY 验证主要编辑／退出流程。三系统 CI 使用 Node.js 22/24；PTY 只在支持 Python `pty` 的 macOS/Linux 运行，Windows 仍需实际终端验收。

`package.json` 的发布白名单排除历史会话、个人脑图和恢复数据。每次交付用 `npm pack --dry-run` 核对实际包内容，`npm pack` 只构建本地包。项目未启用 PDM；维护这些现有文档即可，不初始化额外文档体系。
